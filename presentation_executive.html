Content Security · Network Gate
Zero External Access
No content, link, or resource can be accessed from outside the Murex corporate network
FINANCE ONBOARDING
Not a single link, video, or training file stored in MXBoard can be opened from a computer disconnected from the Murex VPN. It is technically enforced — not a policy, a hard technical block.
1. Encrypted in Database
All resource URLs are stored AES-256 encrypted in Supabase. No media path or link ever appears in the frontend source code or HTTP responses.
Key Control
2. Murex VPN Exclusivity
Any request originating outside the Murex corporate network tunnel is blocked at the IP layer. No exceptions, no workarounds, no bypass route exists.
3. Expiring Signed Tokens
Every content request generates a single-use token with a short TTL. Any link shared externally is cryptographically invalidated the moment it expires.

InfoSec & Compliance
Murex Security Guarantees
Why MXBoard strictly complies with enterprise security standards
FINANCE ONBOARDING
  • Zero Murex Database Writes: MXBoard holds no write credentials or routes to the Murex relational schema. Read-only, always.
  • Resource Isolation (Non-Blocking): No action in MXBoard consumes memory or locks critical tables on the Murex server.
  • End-to-End Encryption: Data in transit encrypted via TLS 1.3 with automatic session token expiration on every request.
  • Role-Based Access Control (RBAC): Strict permission boundaries by role — Trainee, Supervisor, Admin. Zero role escalation possible.
  • Traceability & Audit Logs: Immutable audit trail recording every system event within the middleware layer.
  • VPN-Gated Content: All training materials and media links are blocked at the network layer for requests outside the Murex corporate VPN.
